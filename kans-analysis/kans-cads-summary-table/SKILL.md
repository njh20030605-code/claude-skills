# KANS 越南｜C-ads 品广素材投放决策汇总

把每周的品广数据整理成固定格式的决策表（xlsx），版式和口径与作者的飞书表「KANS_品广素材投放决策_汇总」完全一致，用 2026-09-23~09-29 那一期 25 个素材逐格对账过。

**你（Claude）只负责：收文件 → 跑脚本 → 把校验提示讲清楚 → 交付 xlsx。不要手算、不要改口径。**

## 第 0 步：先问两件事（一次问完）

1. **汇率**：1 USD = 多少 VND？必须用户给，不许自己猜（9.23–9.29 那期用的是 26310）。
2. **分析周期**：脚本会从 TTMS 报告里自动读。用户口头说的「这周 / 上周」不用追问，但**交付时要把实际周期亮出来**让用户确认；报告之间周期不一致时让用户拍板。

## 第 1 步：收文件（告诉用户怎么导）

| # | 数据 | 用户怎么拿 | 必需？ |
|---|---|---|---|
| 1 | **TTMS 种草广告报告**（每个素材一份） | TTMS → Post campaign report → 打开每份报告 → **等页面数字停止滚动（约 5 秒）** → 全选（Ctrl/Cmd+A）→ 复制 → 依次粘进一个 txt（多份直接接着粘）上传；或直接粘在对话里 | ✅ 必需 |
| 2 | **GMV MAX Creative data** | GMV Max 后台按**产品**导出 Creative data，日期 = 分析周期，每个产品一份 xlsx（白/红/素颜霜/377次抛/战痘次抛…有几个传几个） | 强烈建议（没有就算不了总营销 ROI） |
| 3 | **达人订单明细** `affiliate_orders_*.csv` | 联盟营销订单导出，时间 = 分析周期。**等订单结算几天后再导**（只统计「已结算」订单） | 可选（算付费/自然流占比） |
| 4 | **Campaign Report** `Kans--02-Campaign Report-*.xlsx` | 广告后台广告组列表导出，日期选**今天**（取实时状态和日预算） | 可选（取 KOL 名、状态、现行日预算） |

- 用户把报告内容**直接粘在对话里**：原样写进一个 `.txt` 文件再跑，一个字都不要改、不要自己重打数字。
- 用户只给了**截图**：照截图把数字填进 `templates/TTMS结案录入模板.csv`（报告名、消耗、展示量、种草Co、6秒播放数或6sVTR、种草效率、GMV、ROAS、分析周期），**先把填好的表给用户核对，确认后再跑**。
- 报告名必须是 `素材ID_起投MMDD_截止MMDD_产品` 格式（例 `7000000000000000001_0919_0929_377次抛`），脚本靠它认素材。

## 第 2 步：跑脚本

```bash
python3 <本skill目录>/scripts/build_summary.py <上传文件所在文件夹或逐个文件> --fx <汇率> --out <输出目录>
```

- `<本skill目录>` = 这份 SKILL.md 所在的目录；不确定就 `find / -name build_summary.py -path '*kans-cads-summary-table*' 2>/dev/null`。
- `--out` 给目录即可，文件自动命名为 `KANS_C-ads品广素材投放决策汇总_MMDD-MMDD.xlsx`（周期取自报告），目录不存在会自动建。

- 上传文件放哪个目录都行，传文件夹它会自己按**内容**认出四类文件（不看文件名）。claude.ai 里上传文件一般在 `/mnt/user-data/uploads`，产出放 `/mnt/user-data/outputs`。
- 可选参数：`--period "2026-09-23 ~ 2026-09-29"`（覆盖报告里的周期）、`--status-date 10.2`（表头写「E/X 取 10.2 实时状态」，默认取 Campaign Report 文件名里的日期）。
- 依赖只有 pandas + openpyxl。

## 第 3 步：交付

1. 把 xlsx 给用户。里面两页：`汇总`（主表）和 `校验`（用了哪些文件 + 全部提示）。
2. 用几句话转述脚本打印的结果：实际分析周期和汇率、素材数、总营销 ROI 前三、品广质量分前三，**以及每一条 ⚠️ 提示**，并说清楚用户要不要动手：
   - 「页面数字互相对不上」→ 让用户**重新复制那一份报告**发来，换上后重跑再交付（这一行的数不可信）。
   - 「GMV 改用反算」→ 无需处理，差额通常 <$1；介意就重新复制那一份。
   - 「GMV MAX 没找到」→ 问用户是不是少传了某个产品的 Creative 文件。
   - 「GMV MAX 消耗不到 $10」→ 提醒这几行的 GMVMAX ROI 是虚高，别当成表现好。
   - 「订单不到 15 单」「在投但没报告」→ 告知即可。
3. 主动解释一句，免得同事以为错位：**表按「总营销ROI」从高到低排，A 列「序号」是品广质量分的名次（1 最好），所以序号看起来是乱的。两个榜单衡量的东西不同（一个看种草效率、一个看花钱换回的 GMV MAX 收入），排名对不上是正常的。**
4. 状态/现行日预算取的是 Campaign Report 那一天的快照；如果那份导出不是今天的，提醒用户想看最新状态就重导一份。
5. 要放进飞书：在飞书汇总表里新建一页，按惯例命名 `M.D-M.D日-数据（M.D日更新）`（前面是分析周期，括号里是导数据/出表当天），把 `汇总` 页整块复制粘贴过去。
6. **Y 列「新预算」和 Z 列「投流码」留给人填**，不要替用户定预算。

## 表里每一列怎么来的（口径，别改）

| 列 | 含义 | 来源 / 算法 |
|---|---|---|
| A 序号 | 品广质量分排名 | M 从高到低 1、2、3… |
| B 素材(KOL) | 达人 | Campaign Report 广告组名第 2 段；没有就用 GMV MAX 的账号显示名 |
| C 视频ID / D 产品 | — | 报告名；产品简写：White Essence→白，Red serum→红，素颜霜/377次抛/战痘次抛 原样 |
| E 状态 / X 现行日预算 | — | Campaign Report「一级状态」「广告组预算」（同素材多个广告组：有一个投放中就算投放中；预算只加总投放中的广告组，暂停的不算） |
| F 结案消耗 / H 种草Co | USD / 人 | TTMS 报告 Cost / New Consideration size |
| G 结案CPCo | — | F ÷ H |
| I 6sVTR / J 种草效率 | — | 报告页 6-second view-through rate / New Consideration rate（多份报告合并时：6 秒播放数 ÷ 展示量、种草Co ÷ 展示量） |
| K 结案GMV / L 结案ROAS | USD | 报告页 GMV / ROAS。**页面 GMV 缺失或与 F×L 相差 >2% 时改用 F×L**（页面数字是滚动动画，没停就复制会抓到半截值，如「¥6.4」） |
| M 品广质量分 | 0–1 | (mm(I) + mm(J) + (1 − mm(G))) ÷ 3，mm = 本批 min-max 归一化。**只在同一批里比，跨周不可比** |
| N GMVMAX消耗 / P GMVMAX收入 | USD | GMV MAX 导出按 Post ID = 视频ID 汇总（**跨产品文件相加**，消耗为 0 的行收入也算进去）Cost / Gross revenue，÷ 汇率 |
| O GMVMAX ROI | — | P ÷ N |
| Q GMVMAX获客成本 | USD | N ÷ SKU orders |
| R 总营销ROI | — | P ÷ (F + N)，分子**不含**品广 GMV；表按 R 从高到低排（R 两位小数并列时质量分高的在前） |
| S 品广CPM / T GMVMAX CPM / U 总CPM | USD | F÷展示量×1000 / N÷GMV MAX 曝光×1000 / (F+N)÷(两边曝光)×1000；**GMV MAX 曝光 <1000 时 T、U 留空** |
| V GMV付费流占比 / W 自然流占比 | — | 达人订单只取「已结算」，按内容ID汇总：带「店铺广告佣金率」的订单支付金额 ÷ 该素材全部支付金额；W = 1 − V。**已结算单数 <15 的不具统计意义** |

## 常见坑

- **汇率每期都问**，不要沿用上一期。
- 同一素材有**多份报告**（不同起投日的广告组各建了一份）：脚本会自动合并（量相加、比率重算）并提示，正常。
- 某素材在 GMV MAX 里**没找到**：多半是少传了那个产品的 Creative 文件，先问用户再交付。
- 「在投但没报告」的提示：说明 Campaign Report 里有新广告组还没建 TTMS 报告，告诉用户即可，不影响出表。
- 脚本会自查每份报告：种草Co÷展示量 vs 种草效率、6秒播放÷展示量 vs 6sVTR、消耗÷展示量 vs CPM，对不上就提示——这是「复制时页面没加载完」最常见的表现。
- 同一个达人在不同广告组里名字写法不同（如 `Creator A` / `creator.a`）是广告组命名本身的问题，表里照抄，不要自己合并。
- 脚本读不出某份报告（提示「缺 cost/imp/co」）：多半是复制时页面没加载完，或 TTMS 是中文界面标签对不上。让用户重新复制那一份，或你按原文把数字填进录入模板 csv 再跑。
- GMV MAX 的 Post ID 是 19 位数字，脚本按文本读；你自己用 pandas 看数据时也必须 `dtype=str`，否则精度丢失、匹配不上。
