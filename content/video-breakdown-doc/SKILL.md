# 短视频素材拆解文档

把视频**逐秒看完**再动笔，产出能直接放进飞书文档、也能对外展示的拆解。
这套做法来自 2026-10-15 的「挂车短视频素材拆解手册」第 6、7 节，新做的拆解照它的结构和标准来。

## 硬规则（用户明确提过，违反就返工）

1. **逐秒看片**：1 秒 1 帧的总览图全部看完，字幕区按 0.5 秒逐格看；不能凭转写 + 每 3 秒一帧写。
2. **原话以屏幕烧录字幕为准**，转写只用来对时间、补无字幕段落；无字幕的标「（无字幕，据转写）」。
3. **「」只放原话或屏幕文字；“”放概括和观众心理**。改写过的句子不许放在「」里。
4. **人名只按画面标注、字幕或口播点名写**，不按长相猜；**AI 只在画面有标注时写**，标题写了 AI 不算。
5. **产品以画面和字幕为准**：标题里的「次抛」「防晒」可能只是赠品或功效之一，结合包装、字幕和客单价确认主推品。
6. **站在用户视角讲作用**，用大白话。例：377 对比闪充棒 = “教育用户、补充产品心智，解决不知道选哪支的痛点，
   一句话讲清两个产品的区别和功效”；不要只贴「认知型 / 机制型 / 二选一」标签。
7. **完整话术一句不漏、按段落分层**：段名（起～止秒）→ 逐句原话 → 这段对用户在做什么。
8. **文档是对外的**：不写「和官方低质规则冲突」「慎用」「⚠ 易判演戏炒作」「面试时讲出来是加分项」「我会改」。
9. **统计性结论必须由核对文件算出来**（「11 条里 9 条…」），样本只有一两条时不下「某类更好」的结论。
10. 只写拆解部分（见 references/doc-structure.md 的骨架），不加「能力概览」「成果一览」这类包装，用户没要就不加。

## 流程

工作目录用会话 scratchpad 下的新文件夹，下面记作 `$W`；脚本在 `~/.claude/skills/video-breakdown-doc/scripts/`（记作 `$K`）。

**1. 收素材**
- 本地文件：用户给的路径或 `~/Downloads` 里的视频。
- 素材后台：用户的 Chrome 打开素材后台，顶部搜索框输素材 ID，点卡片封面打开详情，
  读 `<video>` 的地址后 `curl` 到 `$W/dl/` 单独文件夹（地址不带签名；用户要求拆这几条即视为同意下载）。
- 给每条编号 v01、v02…，另起干净文件名（原文件名常带编导、剪辑同事的名字，上传前必须换掉），写进 `names.json`。

**2. 预处理**
```bash
python3 $K/prep.py --out $W --names $W/names.json v01=/path/a.mp4 v02=/path/b.mp4
```
出 540p 上传版、16k 音频、1 fps 总览图（sheet_*.jpg）、0.5 秒字幕条（sub_*.jpg）。字幕不在画面 58%～84% 高度时调 `--sub-top/--sub-bottom`。

**3. 转写**（后台跑）
```bash
~/.venvs/whisper/bin/python $K/transcribe_zh.py $W
```

**4. 逐秒核对** → 每条一份 `$W/review/vNN_核对.md`，格式见 `references/review-template.md`。
- ≤ 4 条：自己看完全部 sheet 和 sub 再写。
- \> 4 条：按 `references/review-agent-prompt.md` 派 2～3 个助手并行（每个 3～4 条，按总时长均分）。
- 助手交回后抽查至少一份：话术段数、人名依据、开头 0～5 秒是否逐秒写了。

**5. 解析**
```bash
python3 $K/parse_review.py $W/review $W/scripts.json
```
每条打印段数、原话句数、屏幕文字处数；某段缺「这段对用户在做什么」会点名，回核对文件补上再跑。

**6. 归纳**（只用核对文件里的事实）：一句话总结、结构母版（几段、各段时长、各段代表原话）、
钩子地图（按好奇 / 情绪 / 利益 / 认知分类，只收前三秒的句子，中段句标秒数）、金句公式、可复用做法、重点案例的拆解卡。

**7. 数据**（有投放数据才做）：按 `references/data-benchmark.md` 统一口径取数，`svg_bench.py` 出区间图和统计。

**8. 写文档**：按 `references/doc-structure.md` 的骨架和 XML 写法。逐条拆解大表：
```bash
python3 $K/build_table.py $W/scripts.json $W/rows.json $W/table.xml
```
先 `docs +script --command parse` 校验，再新建或插入。写操作一条一条顺序跑。

**9. 收尾检查**
- `python3 $K/quotes.py $W/scripts.json vNN <写好的 xml>`：「」不是原话的改“”，“”里近似原话的换成真正原话（屏幕文字除外）。
- 画板导出预览图逐张看；视频 `size` 不为 0；文档目录层级对。
- 公开文档用内置浏览器（未登录）打开看一眼。

**10. 对外版**（用户要求时）：整篇复制原文档，只把数据换成指数或排名位置，其余不动，见 `references/data-benchmark.md`；
`scan_sensitive.py` 复查后设公开。

## 交付时跟用户说什么

- 文档链接、写进了哪几节。
- 核对中发现的事实性问题（比如素材标题写的品类和实际主推品不一致、屏幕大字和底部小字的机制前后矛盾）。
- 没能验证的地方（比如浏览器打不开、某条详情页取不到数），直接说，不要省略。
